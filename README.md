# دفتر الديون

**دفتر بسيط لإدارة الديون والسداد** بين العملاء والتجار — تطبيق ويب تقدّمي (PWA) عربي،
من اليمين إلى اليسار، مصمّم كتطبيق جوال (Android-like) لا كموقع ويب، وجاهز للتحويل
لاحقًا إلى Android عبر Capacitor.

---

## ما الذي يعمل الآن؟

| القدرة | الحالة |
|---|---|
| استخدام فردي كامل (عميل أو تاجر) بلا إنترنت وبلا حساب | ✅ يعمل |
| إنشاء دفتر بخطوة واحدة (اسم + دور) | ✅ |
| محلات (عميل) / عملاء (تاجر): إضافة، تعديل، أرشفة، بحث وترتيب | ✅ |
| تسجيل ديون وسدادات بتاريخ ووقت تلقائيين | ✅ |
| الرصيد = مجموع الديون المؤكدة − مجموع السدادات المؤكدة | ✅ المعلّق لا يُحتسب |
| رفض الصفر والسالب، ومنع السداد الأكبر من الرصيد المؤكد | ✅ مختبَر |
| عكس القيود المؤكدة (لا تعديل صامت ولا حذف تاريخ مالي) | ✅ |
| ربط الطرفين بموافقة الطرفين عبر رمز QR قصير العمر لمرة واحدة | ✅ |
| تأكيد/رفض العمليات المشتركة (المنشئ لا يؤكّد عمليته) | ✅ |
| اعتماد الرصيد السابق صراحةً (بلا دمج تلقائي) | ✅ |
| مركز إشعارات + شارات في التنقّل السفلي | ✅ |
| العمل دون اتصال + طابور مزامنة + منع الإرسال المزدوج | ✅ |
| مزامنة لحظية بين الطرفين (Supabase Realtime) | ⏳ الكود جاهز — يحتاج مشروع Supabase حقيقيًا |
| اختبارات | 128 اختبارًا تمر (منطق + محرّك محلي + مسار واجهة كامل) |

## التقنية

React 19 · TypeScript · Vite · Tailwind 4 · React Query · React Router (hash) ·
Zustand · Zod · IndexedDB (idb) · vite-plugin-pwa · Vitest + Testing Library

## المعمار — Ports & Adapters

الواجهة لا تعرف إلا عقدًا واحدًا: `DataSource` (في `src/data/port.ts`).

```
src/core        منطق خالص: المال (وحدات صغرى)، آلة الحالات، الرصيد، التحقق، QR، التواريخ
src/data        المحرّكات: local (IndexedDB) و supabase (Postgres + RLS + Realtime)
src/features    شاشات المستخدم: بداية، دفتر، أطراف، عمليات، ربط، إشعارات، إعدادات
src/app         التوجيه، المزوّدات، التنقّل السفلي، الثيم
src/components  مكتبة الواجهة الموحّدة (أزرار، بطاقات، أوراق، حوارات، تنبيهات)
supabase/       الهجرة SQL الكاملة: جداول + قيود + عروض + دوال مؤمّنة + RLS + Realtime
docs/PLAN.md    الخطة الكاملة والمراحل الـ16
```

**لماذا محرّكان؟** المجرّد المحلي يعمل بلا خادم إطلاقًا (استخدام فردي فوري، بلا حساب،
بلا إنترنت)؛ والمحرّك السحابي يضيف الربط بين الطرفين والمزامنة اللحظية. الاثنان ينفّذان
نفس العقد ونفس القواعد المالية، لذا الواجهة والاختبارات لا تتغير.

## تفعيل الوضع السحابي (اختياري)

1. أنشئ مشروعًا في Supabase ثم نفّذ `supabase/migrations/0001_init.sql` في SQL Editor.
2. أضف متغيّرات البيئة (مفتاح `anon` فقط — لا `service_role` في المتصفح أبدًا):

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

3. أعد البناء. سيتحوّل التطبيق تلقائيًا إلى الوضع السحابي، وسيُحمَّل المحرّك الثقيل عند
الحاجة فقط (code-splitting).

## قواعد ثابتة لا تُخالف

1. **لا يُطلب الربط أبدًا** لأجل وظيفة مستقلة — لا وجود لرسالة «يجب ربط حسابك أولًا».
2. **المال ليس Float**: وحدات صغرى صحيحة داخليًا، و`bigint`/`numeric(18,2)` في القاعدة.
3. **لا حذف تاريخ مالي**: التصحيح بعكس مرتبط بالأصل، والإلغاء قبل التأكيد.
4. **لا ثقة بالاسم أو الهاتف**: التأكيد بحساب الطرف الحقيقي ووقت التأكيد.
5. **لا أسرار في الواجهة**: مفتاح `anon` فقط + RLS صارم + كتابة مالية عبر دوال مؤمّنة.
6. **البساطة للمستخدم والتعقيد في الخلفية**.
7. **أرقام الهاتف بلا مفتاح دولة** (لا `967` ولا `+`): تُحفظ وتُعرض محلية (`771234567` / `771 234 567`)، وأي مفتاح دولة يكتبه المستخدم يُزال.

## الخصوصية

يعمل التطبيق افتراضيًا بمحرّكه المحلي: البيانات في قاعدة بيانات المتصفح (IndexedDB) على
جهاز المستخدم فقط، بلا خادم. في الوضع السحابي، كل جدول محمي بسياسات وصول تمنع أي مستخدم
من رؤية أو تعديل بيانات غيره.

## التحديث التلقائي (لا نسخة قديمة بعد الآن)

- **أول تحديث للصفحة يكفي:** نسخة HTML لا تُخزَّن مسبقًا في Service Worker مطلقًا، بل تُقرأ من الشبكة أولًا، فلا يعرض التطبيق نسخة قديمة من الواجهة.
- **فحص تلقائي للتحديثات:** عند إقلاع التطبيق، وعند العودة إلى التبويب، وعند رجوع الشبكة، وكل دقيقة.
- **تولّي فوري للنسخة الجديدة:** `skipWaiting` + `clientsClaim`، ومعهما إعادة تحميل واحدة تلقائية عند تولّي الـ SW الجديد (بحرس يمنع أي حلقة إعادة تحميل).
- **في وضع التطوير:** يُزال أي Service Worker قديم وتُفرَّغ الكاشات تلقائيًا، فما تراه في المعاينة هو آخر تعديل دائمًا.
- عند الانقطاع: التنقّل يعمل من كاش `app-shell` (NetworkFirst بمهلة 4 ثوانٍ)، والملفات من precache، والعمليات غير المرسلة تبقى في الطابور بانتظار المزامنة.

## بوابة التثبيت (لا يُفتح الدفتر من المتصفح)

- **الملفات:** `index.html` (حاويتان + تصنيف قبل أول رسم) · `public/install-gate/style.css` · `public/install-gate/app.js` — HTML/CSS/JS قياسي بلا أي مكتبة، ولا يعتمد على CSS التطبيق.
- **كشف الحالة:** `display-mode: standalone|minimal-ui|fullscreen|window-controls-overlay` أو `navigator.standalone` ⇒ التطبيق مثبّت: يُعرض `#app-content` وتُخفى `#install-screen`. غير ذلك ⇒ يُخفى `#app-content` (مع `inert` + `aria-hidden`) وتُعرض `#install-screen`.
- **كروم/إيدج/بريف:** يُلتقط `beforeinstallprompt` (مع `preventDefault` لحرمان المتصفح من بانره) ويُربط بزر `#install-button`؛ `prompt()` يُستخدم مرة واحدة، ثم تُعرض لوحة «تم التثبيت — افتح من الشاشة الرئيسية».
- **iOS Safari:** لا `beforeinstallprompt` ⇒ الزر مخفي وتظهر ثلاث خطوات مرقّمة: «مشاركة» ← «إضافة إلى الشاشة الرئيسية» ← «إضافة». نميّز سفاري الأصلية بوسم `Version/…Safari` (كل متصفحات iOS WebKit)؛ والمتصفحات داخل التطبيقات وفايرفوكس تأخذ الدليل اليدوي.
- **إعادة التصنيف عند «الدخول» فقط:** `visibilitychange` / `pageshow` / `focus` / تغيّر `display-mode` / `appinstalled` — بلا أي نافذة منبثقة أثناء الاستخدام.
- **لا شاشة بيضاء:** ظهور البوابة مربوط بخاصية `data-install-gate` التي يضبطها سكربت مصغّر في `<head>` قبل أول رسم؛ وأي استثناء في `app.js` أو تعطّله ⇒ `data-install-gate="app"` (التطبيق يعمل).
- **مفاتيح التحكّم:** `?installgate=off` (تجاهل البوابة لهذه الجلسة، تُخزَّن في `sessionStorage`) · `?installgate=force` (اختبار الشاشة في وضع standalone) · `CONFIG.allowSkip` في `app.js` إن أردت رابط «المتابعة في المتصفح» للجميع.
- **منطق البوابة مُختبَر:** `src/app/installGate.test.ts` (14 اختبارًا) يقيّم `public/install-gate/app.js` نفسه داخل jsdom ويقلّب: standalone، iOS، معامِلات الرابط، وربط `beforeinstallprompt`.
- **ملاحظة نشر:** الأصول بمسارات مطلقة (`/install-gate/…`) — إن نُشر المشروع في مسار فرعي فاستخدم `base` في `vite.config.ts` وروابط نسبية.

## استيراد من جهات الاتصال

بجانب حقل رقم الهاتف في نموذج إضافة/تعديل العميل أو المحل:

- على أندرويد (كروم) يُفتح **منتقي جهات الاتصال في النظام** بلمسة واحدة ويملأ الاسم والرقم.
- على بقية الأجهزة (أو عند تعذّر المنتقي) يُختار ملف تصدير: `.vcf` من أندرويد/آيفون أو `.csv` من Google Contacts، ويُحلَّل **داخل المتصفح** بلا رفع لأي خادم.
- إن احتوى الملف عدة جهات تظهر قائمة اختيار مع بحث، والاسم يُملأ إن كان الحقل فارغًا والرقم يُملأ دائمًا، ويُوحَّد الرقم **محليًا بلا مفتاح دولة** (يُزال `+967` أو `00967` أو الصفر الذي في البداية: `+967771234567` ← `771234567`).

## الحساب: الإنشاء والدخول والاستعادة

> **البريد الإلكتروني غير مطلوب إطلاقًا.** التسجيل **الاسم + رقم الهاتف + كلمة المرور** فقط،
> ويُضاف البريد لاحقًا من الإعدادات متى أراد المستخدم المزامنة بين الأجهزة (`الإعدادات ← الحساب السحابي`).

> **كلمة المرور: 4 خانات وما فوق، ولا شيء غير ذلك.** لا تُفرض حروف ولا رموز ولا حروف كبيرة — أرقام وحدها
> مقبولة (`1234`). التنبيه الوحيد أن تكون 4 خانات على الأقل وأن يتطابق حقلا الكلمة وتأكيدها.
> (كلمة مرور الحساب السحابي وحدها تطلب 6 خانات — شرط مزوّد الحساب.)

### على هذا الجهاز (الوضع الافتراضي)
- **شاشة البداية**: يحدّد المستخدم نوعه مرة واحدة — **«أنا عميل»** أو **«أنا تاجر»** (اختيار ثم **«متابعة»**) —
  ولا يُعاد الاختيار في الصفحة التالية (يظهر النوع كنص: «الحساب: عميل/تاجر»).
- **إنشاء حساب جديد**: **الاسم + رقم الهاتف + كلمة المرور + تأكيدها** (والعملة)، وتحته رابط
  **«هل نسيت كلمة المرور؟»**. لا يوجد أي حقل بريد إلكتروني في هذه الشاشة.
- **تُحفظ بيانات الدخول وبيانات المستخدم** على الجهاز (وبصمة كلمة المرور PBKDF2-SHA256 + ملح):
  بعد **تسجيل الخروج** يدخل بـ**رقم هاتفه وكلمة المرور** فيجد دفتره كما تركه.
- **تسجيل الدخول**: رقم الهاتف + كلمة المرور، وبجانبه بطاقة **«الحسابات على هذا الجهاز»** للدخول السريع.
- **الرقم يُقبل بأي صيغة** (`0771234567` · `771234567` · `+967 771 234 567` · `00967771234567`) ويُخزَّن
  محليًا بلا مفتاح دولة. والأرقام المحفوظة في نسخ سابقة **بمفتاح دولة تُفتح أيضًا** وتُوحَّد تلقائيًا عند أول دخول.
- **«هل نسيت كلمة المرور؟»** على الجهاز: يُدقَّق رقم الهاتف المسجّل ثم تُعيَّن كلمة مرور جديدة.
- **تغيير كلمة المرور** من `الإعدادات ← الأمان` في الوضعين: كلمة مرور الجهاز تتغيّر بإدخال الكلمة الحالية.
- **الخصوصية**: كل شيء محفوظ في هذا الجهاز وحده (IndexedDB) — لا خادم ولا حساب سحابي لاستخدام الدفتر.
- **لا بريد داخل حساب الجهاز**: مستند المستخدم على الجهاز يحمل الرقم وحده (مخطط قاعدة الجهاز الإصدار 2
  يُزيل فهرس البريد القديم بلا حذف أي بيانات).

### الحساب السحابي (اختياري — للمشاركة والربط)
- **إضافته من الإعدادات**: `الإعدادات ← الحساب السحابي ← أضف بريدك الإلكتروني` ⇒ يُنشأ حسابك السحابي
  بالاسم والهاتف والنوع نفسه، **ويُنقل دفترك المحلي إليه** (دمج بلا حذف وبلا تكرار)، ثم تُشغَّل المزامنة.
  وإن كان بريدك مسجّلًا مسبقًا (أنشأته على جهاز آخر) يكفي إدخال كلمة مروره ليدخل بحسابك نفسه.
- **بريد الحساب السحابي** يطلب 6 خانات على الأقل (شرط مزوّد الحساب)، وبعد الربط يُدخل به من أي جهاز آخر.
- عند تفعيل **تأكيد البريد** (يحتاج SMTP خاصًا — راجع `docs/supabase-connect.md` القسم 5): يُحفظ دفترك
  مؤقتًا ويُنقل تلقائيًا بعد فتح رابط التأكيد ودخول الحساب — بلا فقدان بيانات. وإن وصل الرابط بصيغة
  Supabase الافتراضية (`#access_token=…`) يعالجه التطبيق أيضًا.
- **فصل الحساب السحابي** متاح من القسم نفسه: يعود التطبيق للعمل على الجهاز وحده، والدفتر المحلي لا يُحذف.

## تسجيل دين أو سداد (بلا خطوات زائدة)

- من الرئيسية: زر **«دين»** أو **«سداد»** — كل زر يفتح نافذته المستقلة (لا تبديل للنوع داخل النافذة).
- **إن كان هناك أكثر من طرف** (عملاء التاجر / محلات العميل): تظهر **قائمة الأطراف أولًا** مع بحث وترتيب ← تختار الطرف ← تُفتح نافذة **المبلغ والتفاصيل** ولوحة الأرقام والمؤشر على المبلغ.
- **إن كان هناك طرف واحد فقط** (محل واحد عند العميل، أو عميل واحد عند التاجر)، أو فُتحت النافذة من صفحة الطرف: ندخل إلى **المبلغ مباشرة** بلا قائمة.
- النافذة بلا عنوان في الأعلى وبلا شرح في الأسفل — المساحة كلها للوحة الأرقام.
- تنبيه الحساب الموثّق يظهر فقط عند الحاجة: العملية تُسجَّل مباشرة لكنها لا تُحتسب في الرصيد حتى يؤكّدها الطرف الآخر.

## تصحيح عملية خاطئة (بلا «عكس» وبلا حذف)

- **لا يوجد زر «عكس عملية»** — وُجد سابقًا وأُلغي لأنه معقّد بلا داعٍ.
- لتصحيح أي عملية: سجّل **العملية المعاكسة** — سدادًا مقابل دين سُجّل خطأً، أو دينًا مقابل سداد. الرصيد يتعدّل فورًا.
- لا يُحذف ولا يُعدّل سجل مالي أبدًا: العملية الأصلية تبقى كاملة في السجل مع وقتها ومنشئها وحالتها.

## صوت إتمام العمليات

- نغمة قصيرة تُولَّد داخل الجهاز (Web Audio — بلا أي ملف صوتي) عند **اكتمال كل عملية**: تسجيل دين/سداد، تأكيد، رفض، إلغاء، إضافة عميل، ربط، اعتماد رصيد.
- نغمة مختلفة قليلًا عندما تكون العملية **بانتظار تأكيد الطرف الآخر**، ونغمة منخفضة عند الفشل، مع اهتزاز خفيف على أندرويد.
- مفتاح تشغيل/كتم في **الإعدادات ← التفضيلات ← صوت إتمام العملية**.

## النسخة الاحتياطية (نسخة واحدة دائمًا)

- **الإعدادات ← النسخة الاحتياطية**: إنشاء نسخة، تنزيل ملف `.json`، استعادة من ملف، حذف النسخة.
- **كل نسخة جديدة تستبدل السابقة تمامًا** — لا تتراكم ملفات ولا تمتلئ مساحة التخزين.
- **للتاجر: نسخة تلقائية في نهاية كل يوم** (وعند إخفاء التطبيق وعند منتصف الليل) وتستبدل نسخة اليوم السابق. الخيار متاح لأي دور من نفس الشاشة.
- النسخة تُحفظ داخل الجهاز فقط (IndexedDB) ولا تُرسل لأي خادم.
- الاستعادة **دمج آمن**: تُضاف السجلات الناقصة فقط، ولا يُحذف أو يُستبدل سجل موجود، ولا تتكرر العمليات (معرّف فريد لكل عملية). لا تُستعاد حالة الربط — الربط يحتاج موافقة الطرفين من جديد — ولا تُفرض العمليات المشتركة.

## موثوقية الإقلاع (لا شاشة معلّقة)

- **لا ترقية لمخطّط قاعدة البيانات**: النسخة الاحتياطية تُخزَّن في مخزن `meta`، فلا يوجد ما يُحجب عند وجود تبويب قديم مفتوح.
- **فتح مرن للقاعدة**: إن كانت القاعدة أحدث أو حُجبت الترقية، نفتحها بأي إصدار متاح ونكمل العمل.
- **مهلة فتح (2.5 ثانية)**: لا انتظار أبدي، والفشل يُعرض برسالة عربية واضحة مع زر إعادة محاولة، وكل محاولة جديدة تعيد الفتح فعلًا.
- **مخرج في شاشة البداية**: بعد 6 ثوانٍ تظهر رسالة وزر «إعادة المحاولة»، وكذلك أي خطأ في الجلسة أو الملف الشخصي.

## كشف الحساب PDF (للتاجر والعميل)

- من **صفحة أي عميل (عند التاجر)** أو **أي محل (عند العميل)**: زر **«تصدير كشف حساب PDF»** (وأيقونة في الترويسة).
- تختار الفترة: **كل الفترة / هذا الشهر / آخر 30 يومًا**، وترى ملخّصًا قبل التصدير (الرصيد المؤكد، عدد العمليات المؤكدة والمعلّقة).
- ثم **مشاركة** الملف عبر تطبيقات الجهاز (واتساب، تيليجرام، البريد…) أو **تنزيل**ه على الجهاز.
- اسم الملف: `كشف-<اسم الطرف>-<التاريخ>.pdf`. التوليد **داخل الجهاز بالكامل** بلا أي خادم، ويعمل بلا إنترنت.
- الكشف: ترويسة باسم الدفتر والطرف، ثلاث بطاقات (إجمالي الدين المؤكد / إجمالي السداد المؤكد / المتبقي)، جدول بالتاريخ والنوع والبيان والمبلغ والحالة، وتذييل بالصفحة.
- **الرصيد من العمليات المؤكدة فقط**، والمعلّق يظهر موسومًا «بانتظار التأكيد» ولا يدخل الرصيد.
- محرّك PDF (pdf-lib + الخطوط) يُحمَّل **عند التصدير فقط**، فلا يثقل فتح التطبيق.

## أرقام الهاتف (بلا مفتاح دولة)

- عند الكتابة أو الاستيراد من جهات الاتصال: يُقبل الرقم بأي صيغة شائعة — `0771234567` · `771234567` · `+967 771 234 567` · `00967771234567` · أرقام عربية `٧٧١٢٣٤٥٦٧`.
- **التطبيق لا يُضيف أي مفتاح دولة**: يُخزَّن الرقم محليًا (`771234567`) ويُعرض مقروءًا (`771 234 567`) في كل الشاشات.
- **مفتاح الدولة لا يظهر في الكشوف PDF أيضًا**: كشف الحساب يُطبع فيه رقم الطرف بلا مفتاح دولة، حتى لو كان الرقم محفوظًا من نسخة سابقة بمفتاح (`+967…`) — يُعرض محليًا.
- الرقم المحلي يُستخدم في البحث، وفي زر الاتصال (`tel:`)، وفي نص مشاركة الكشف.

## الخروج من التطبيق (حارس الرجوع)

- **أنت في «الرئيسية» وضغطت زر الرجوع؟** يُعتبر ذلك **محاولة خروج من التطبيق** — حتى لو وصلت إلى الرئيسية من شاشة أخرى — ولا يخرج التطبيق إلا بعد **تأكيدك**.
- الحارس يظهر **نافذة من داخل التطبيق بتصميمه** (لا نافذة نظام المتصفح): «الخروج من التطبيق؟» مع **«خروج»** و**«البقاء في التطبيق»**.
- **الرجوع في أي شاشة أخرى** يبقى تنقّلًا عاديًا داخل التطبيق (بلا أي نافذة).
- **إن كانت هناك نافذة مفتوحة** (تسجيل دين/سداد أو نافذة تأكيد) فالرجوع **يُغلق النافذة أولًا** — كسلوك أندرويد — ولا يعرض نافذة الخروج.
- **رجوع آخر ونافذة الخروج مفتوحة** يُغلقها (سلوك أندرويد المعتاد).
- عند تأكيد الخروج: يُحاوَل إغلاق التطبيق مباشرة (التطبيق المثبّت على الجوال)، وإلا يُرجَع بك خارج سجل التطبيق إلى الصفحة التي كنت فيها قبل فتحه؛ وإن كان التطبيق أول صفحة في التبويب تظهر رسالة تدلّك على الإغلاق من المتصفح.
- أثناء **شاشة القفل** يبقى الرجوع خروجًا مباشرًا (لا يُطلب تأكيد قبل التحقق من هويتك).

## قفل التطبيق (بصمة + باترن)

- **الإعدادات ← الأمان ← قفل التطبيق** (ويظهر اختصاره أيضًا في الإعدادات).
- **قفل بالبصمة**: عند **الدخول** إلى التطبيق **تبقى شاشة التطبيق فارغة تمامًا** (بلا أيقونة وبلا زر «افتح بالبصمة» وبلا نصوص) — نكتفي **بنافذة البصمة التي يُظهرها الجهاز/المتصفح نفسه** (WebAuthn — بصمة/وجه/رمز الجهاز). تُطلب تلقائيًا بلا ضغط أي زر، **مرة واحدة فقط لكل عملية دخول**.
- **لا مطالبات وأنت داخل التطبيق**: لا إعادة طلب تلقائية ولا تذكير عند تبدّل رؤية الصفحة، ولا نفتح نافذة النظام والتطبيق في الخلفية (نؤجلها إلى لحظة الدخول). وإخفاء الصفحة الذي تسببه نافذة البصمة نفسها لا يُحتسب غيابًا فلا يُعيد القفل.
- **إن أُلغيت المطالبة أو تعذّرت أو لم يكن للجهاز مستشعر** ⇐ **يظهر الباترن** مع زر «إعادة المحاولة بالبصمة» (طلب صريح من المستخدم)، فلا يبقى المستخدم عالقًا خارج دفتره.
- **باترن احتياطي إلزامي** عند تفعيل البصمة: 4 نقاط على الأقل، يُخزَّن **مشتقًّا (PBKDF2-SHA256 + ملح عشوائي)** لا كنص صريح.
- **إعادة القفل**: عند كل تشغيل، وعند العودة للتطبيق بعد غياب أطول من 15 ثانية.
- **إنشاء الباترن من خطوتين** (إنشاء ثم تأكيد): بعد إتمام الخطوة الأولى تُفرَّغ اللوحة فورًا ويمكن إدخال باترن التأكيد — إصلاح لخلل سابق كان يعلّق اللوحة على الباترن الأول.
- لا تُخزَّن أي بيانات بصمة في التطبيق ولا تُرسَل لأي خادم — التحقق يتم في جهازك.

## حقوق المصمم

- سطر خفيف أسفل **كل صفحات التطبيق**: «تصميم وتطوير: شرف غالب قحطان» مع رابط تواصل واتساب.
- وبطاقة كاملة **«تواصل مع المصمم»** أسفل شاشة الإعدادات (واتساب + البريد الإلكتروني).
