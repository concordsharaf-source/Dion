## 2026-09-23 - Reusing Intl.Collator and Precomputing Arabic Search Strings
**Learning:** In lists sorted/filtered by Arabic party names, calling `localeCompare(..., 'ar')` repeatedly during sort comparisons creates high overhead because JS engines instantiate or lookup collators on every compare call. Additionally, running multi-regex normalization (`normalizeArabic` & `normalizePhone`) inside search filters on every keystroke incurs unnecessary calculation. Precomputing normalized search strings in `summarizeParties` and using a static `Intl.Collator('ar')` instance makes party filtering and sorting significantly faster.
**Action:** Precompute searchable normalized properties when building summary objects and reuse shared `Intl.Collator` instances for locale-aware sorting.
